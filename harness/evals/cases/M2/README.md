# Набір кейсів M2 (гейт M2)

Детерміновані кейси для кожного тесту з критерію виходу M2 (`05-eval-base.md` §8).
Кожен кейс — `kind: pytest`, що вказує на тести, які покривають **детерміновану**
частину відповідного T-тесту.

```
uv run rh eval run --suite M2
uv run rh --format text --lang uk eval report --suite M2
```

Поточний стан: **20/20 pass** (`evals/results/M2-<дата>.json`).

## Що тут НЕ покрито (лишається автору / CI з LLM)

Гейт M2 (`§8`) крім детермінованих 100% вимагає **семантичних baseline** і
**холдауту** — їх не можна прогнати офлайн без моделі:

- **Семантичні baseline на F4-W** (фіксований model ID з `model-tiers.yaml`,
  фіксований бюджет, n на метрику): MX (recall/precision витягу), MV (macro-F1
  вердиктів + recall критичних), MS (recall seeded defects D1–D14); **MF = 0 для
  critical**; MA для T49; T57 — baseline частки збережених фраз. Інтервал Вілсона
  95%, у звіті завжди n. Прогін — `С` (з LLM у хості).
- **Холдаут F4-H**: автор прогонить сам (`rh eval run --suite holdout` за
  `08-evals-runbook.md`); у git — лише агрегати в `holdout-log.jsonl` і
  `holdout.lock.json`. Агент у холдаут не заходить (H1).
- **Нуль вигаданих джерел у draft export** — перевіряється на семантичному
  прогоні експорту F4-W.
- **Гейт M2 — рішення автора** (H14): агент готує звіт, рішення записує автор у
  журнал результатів.
