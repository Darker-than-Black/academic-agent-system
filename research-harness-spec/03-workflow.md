# Дослідницький процес і участь людини

Розрізняємо `document_kind` (article/report/thesis) і `study_kind` (empirical/literature/theoretical). У MVP повністю підтримується empirical + article. Зміна формату документа не змінює науковий статус доказів.

## Мінімум для старту

Тема або питання, тип документа та опис наявних матеріалів: `none`, джерела, дані, код чи готові результати. Мова й обмеження можуть мати явні попередні значення. Без матеріалів агент може робити discovery і планування. Для результативних емпіричних тверджень потрібні фактичні runs або позначені як external результати з перевірюваним походженням.

## Етапи

| Етап | Робота агента | Результат і умова переходу | Участь людини |
|---|---|---|---|
| Intake | Інвентаризує файли, формулює питання, виявляє невідоме | brief, матеріали, припущення | Уточнює мету |
| Discovery | Шукає релевантні та суперечливі роботи; веде пошуковий журнал | source registry, evidence notes, прогалини | Визначає межі теми |
| Protocol | Пропонує гіпотезу, baseline, метрики, splits, аналіз, бюджет | versioned protocol | G1: схвалює питання і протокол |
| Evidence | Імпортує/виконує runs, зберігає stdout, config і outputs | run manifests, перевірені artifacts | G2: схвалює суттєві відхилення від протоколу |
| Analysis | Обчислює таблиці, невизначеність; шукає альтернативні пояснення | result rows, analysis scripts, limitations | Оцінює достатність доказів |
| Argument | Складає contribution map, тези та контрдокази | claim ledger, outline | Узгоджує ключову інтерпретацію |
| Draft | Пише методи/результати/обговорення; абстракт оновлює останнім | manuscript.md, references.bib | Редагує будь-який розділ |
| Review | Зіставляє текст із джерелами, числами, протоколом | findings, coverage, unresolved | Розв'язує методологічні суперечки |
| Package | Будує snapshot, checklist, disclosure та пакет матеріалів | verified bundle або draft bundle | G3: схвалює фінальну версію для передачі |

Це залежності, а не незворотний конвеєр. Чернетку можна створювати раніше з явними пропусками. Невдала гіпотеза є допустимим результатом. Після review можна повернутися до джерела, аналізу чи протоколу; новий протокол не переписує історію старого.

G1/G2/G3 прив'язані до hash артефактів і збереженого рішення користувача. Згода на виправлення стилю не є згодою змінити первинну метрику. Повторювати запит для вже схваленого незміненого scope не потрібно. Фінальний gate не означає автоматичну подачу статті.

## Критичні методологічні правила

Для ML: відокремити train/validation/test; зафіксувати baseline і критерій порівняння; розрізняти незалежні повтори та повторні вимірювання; не називати std довірчим інтервалом; показувати негативні результати; задокументувати добір гіперпараметрів і обчислювальні ресурси. Конкретний тест, кількість seeds і допустиму похибку визначає протокол, універсального числа немає.

Для огляду: narrative review не називати systematic review. Для systematic потрібні стратегія пошуку, критерії включення, журнал screening, оцінка якості/ризику упереджень і придатна схема синтезу. PRISMA — рамка звітування, не автоматична гарантія якості методики.

Для теорії: ledger тверджень посилається на припущення, леми та докази. LLM-review не дорівнює формальній верифікації. Це окреме розширення.

Для дисертації: thesis index посилається на study IDs та версії розділів; потрібні спільна дослідницька лінія, межі внеску, узгоджений словник, перехресні посилання, авторство/співавторство і профіль установи. Структуру визначають галузь, університет і керівник — не універсальний шаблон IMRaD.

## Методологічні джерела

- [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist): узгодження claims зі scope результатів, обмеження, відтворюваність, деталі експерименту. Використовується як приклад профілю ML, не обов'язковий стандарт для всіх робіт.
- [PRISMA 2020](https://www.prisma-statement.org/prisma-2020-statement): контроль повноти звітування систематичних оглядів.
- [Cornell thesis guide](https://gradschool.cornell.edu/academic-progress/degrees-fields/research-degree-requirements/thesis-dissertation/writing-your-thesis-dissertation/guide-to-writing-your-thesis-dissertation/): приклад розділення вимог установи до оформлення та вимог комітету до змісту. Не замінює вимог установи користувача.
