# ADR-013 — Evidence як сімейство типів

Статус: прийнято 2026-10-27 (2.5 §4, §12; MVP-гілки — рішення автора 2026-10-27).

## Контекст
Контракти v0.1 (Run, ResultRow) розраховані на ML-експерименти. MVP тепер включає огляд і концептуальну статтю; надалі — опитування, інтерв'ю, педагогічний експеримент.

## Рішення
1. Абстрактний Evidence із спільним envelope (id, schema_version, producer, inputs з hash, created_at) і типами:
   - `excerpt` (точний фрагмент джерела з locator) — усі гілки;
   - `synthesis_matrix` (рядки: джерело × вимір порівняння, з посиланнями на excerpts) — literature;
   - `premise` / `definition` (засновання з джерелом або явна позначка «припущення») — conceptual;
   - `run` + `result_row` — ML;
   - `dataset`, `transcript`, `codebook` — LATER (quantitative, qualitative).
2. Claim посилається на evidence будь-якого типу; правила підтримки залежать від типу.
3. `study_subtype` визначає, які типи evidence обов'язкові для протоколу.

## Альтернативи
- **Окремі незв'язані моделі для кожної гілки** — відхилено: дублювання claim ledger і перевірок.
- **Узагальнити Run на все** — відхилено: огляд не має runs; штучне узагальнення ламає семантику.

## Наслідки
- Claim schema v0.1 розширюється полем типу evidence.
- Нові гілки додаються новими типами без зміни ledger.

Пов'язане: FR-29, FR-05, FR-06, ASR-01, T30.
