# ADR-001 rev.2 — Хости: Claude Code CLI і Codex на ноутбуці

Статус: прийнято 2026-10-27 (рішення координатора і кроку 1, 2026-10-27). Замінює v0.1 ADR-001 у частині вибору хостів; принцип «без власного LLM-runtime» лишається.

## Контекст
v0.1 ADR-001: workflow запускається в наявному агентному runtime (Codex або Claude Code), harness — інструкції + локальний CLI. Початковий опис проєкту в claude.ai орієнтувався на мобільний застосунок і голос. Координатор вирішив: цільові хости — Claude Code CLI і Codex на ноутбуці. Крок 1: `AGENTS.md` одразу, Codex-адаптер — у M3.

## Рішення
1. Цільові хости — Claude Code CLI і Codex на ноутбуці. Мобільний застосунок і голос — не цільові сценарії.
2. Спільні правила агента — у `AGENTS.md`; `CLAUDE.md` лише посилається на нього.
3. Перший host-адаптер — Claude Code (M1–M2); адаптер Codex і перевірка паритету (NFR-13) — M3.
4. Уся перевірка, критична для коректності, виконується CLI `rh`; hooks і slash-команди — лише зручність.
5. Синтаксис команд, hooks і skills кожного хоста перевіряється за актуальною документацією на момент реалізації.

## Альтернативи
- **Мобільний застосунок як основний сценарій** — відхилено: немає локального shell, файлового стану і git-процесу, потрібних для provenance і PR.
- **Лише один хост** — відхилено: автор хоче обидва; спільне ядро робить другий адаптер дешевим.
- **Власний LLM-runtime** — відхилено ще у v0.1: більша поверхня підтримки, потрібні окремі ключі.

## Наслідки
- Опис проєкту в claude.ai суперечить рішенню, доки автор його не оновить; чинною вважається мета з `00-stage0-plan.md`.
- Фонове виконання на ноутбуці — LATER (ADR-015).
- Тест T42 (паритет хостів) — критерій виходу M3.
