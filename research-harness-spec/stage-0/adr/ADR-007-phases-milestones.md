# ADR-007 rev.3 — Фази проєкту Е0–Е3 і milestones реалізації M1–M6

Статус: прийнято 2026-10-27 (рішення автора, крок 1 Р2). rev.2 — 2026-10-28 (рішення автора: дисертаційний шар — M4, ML-гілка — M6). rev.3 — 2026-10-28 (повна дослідницька лабораторія в MVP, ADR-020).

## Контекст
У `09-roadmap.md` «етапи 0–5» — кроки реалізації; у плані проєкту «етапи 0–3» — фази (спека → розробка → тест на статті → валідація). Однакові назви означали різне. Якість перевіряється на кожному етапі розробки.
Графік автора (2026-10-28): розробити harness, перевірити на одній тестовій статті і одразу писати другу статтю для публікації та дисертацію. Отже, дисертаційний шар потрібен до кінця пілоту; ML-гілка для освітніх наук менш нагальна.

## Рішення
1. **Фази проєкту:** Е0 — вимоги і спека; Е1 — розробка harness; Е2 — тест на реальній статті; Е3 — валідація якості і доопрацювання.
2. **Milestones реалізації:**
   | Milestone | Зміст |
   |---|---|
   | M1 | Ядро: схеми, стан, snapshots, intake + G0, rule packs, робочий простір, дерево одиниць |
   | M2 | Вертикальний зріз literature / conceptual: лабораторія (доступ до літератури, локальна бібліотека зі звіркою цитат, робочий стіл синтезу, журнал), дослідницький цикл, claims, текст, підсумки, контекстні пакети, export .docx |
   | M3 | Gates, перевірки і аналітична пісочниця: G1–G3, GE, багаторівнева перевірка, перетини, AI-use, verified export, import .docx, адаптер Codex; пісочниця, реєстр датасетів, tuple-валідатори, графіки з даних, Codex-критик (опційно) |
   | M4 | Дисертаційний шар: thesis index, публікаційний план, вступ, карта внеску, обсяг і оформлення |
   | M5 | Пілот: тестова стаття автора з повною лабораторією, A/B(/C), порівняння критиків; перевірка модуля дисертації на синтетичному fixture; рішення keep / simplify |
   | M6 | ML-специфічне: ML-runs, протоколи seeds / splits, rule pack `ml-empirical`, важкі обчислення |
   MVP = M1–M5. Зміст — `03-requirements-v0.2.md` §7.
3. Кожен milestone має критерій виходу — набір тестів із `05-eval-base.md` §8 — і не вважається завершеним без їх проходження.
4. Негативний результат пілоту (B не кращий за A) — підстава спростити harness, а не розширювати scope.

## Альтернативи
- **Залишити нумерацію roadmap v0.1** — відхилено: колізія назв.
- **Один довгий етап розробки без milestones** — відхилено: немає ранньої перевірки вертикального зрізу.
- **M4 = ML і дисертація разом (rev.1)** — замінено: найбільший milestone відсував би пілот і старт дисертації.
- **Дисертаційний шар після пілоту (M6)** — відхилено: автор починає дисертацію одразу після пілоту.

## Наслідки
- `09-roadmap.md` і `IMPLEMENTATION.md` переписуються в spec v0.2 з новими назвами.
- Tuple-валідатори, типи run і графіки з даних (FR-05, 06, 18; NFR-08) потрібні лабораторії для відкритих освітніх даних і реалізуються в M3; M6 містить лише ML-специфічне. Контракти Run і ResultRow закладаються в схеми M1.
