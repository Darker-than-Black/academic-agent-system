# ADR-010 rev.2 — 6 логічних ролей, ≤3 типи execution context, паралельні екземпляри

Статус: прийнято 2026-10-27 (рішення автора, крок 1 Р9). rev.2 — 2026-10-28 (рішення автора: обов'язкова мультиагентна робота для великих документів, перевірка на найвищому рівні). Уточнює v0.1 ADR-005.

## Контекст
v0.1: один основний агент + опційний reviewer. Addendum §6: ролі orchestrator, planner, researcher, scientific analyst, writer, critic; «науковець — джерело істини» замінено на оцінку підтримки тверджень. Однакова модель з однаковими джерелами не дає незалежної експертизи лише через різні назви ролей.
rev.1 тримала writer в основному сеансі. Для дисертації (ADR-019) основний сеанс переповнюється, тому написання переходить у свіжі контексти на кожну одиницю.

## Рішення
1. Шість логічних ролей як набори відповідальності (матриця — `02-lifecycle.md` §7).
2. Не більше трьох **типів** execution context; кожен тип може мати багато паралельних екземплярів:
   | Тип | Ролі | Що бачить | Межа |
   |---|---|---|---|
   | Оркестратор (основний сеанс) | orchestrator, planner | Intake, status, `structure.yaml`, `map.md`, підсумки, findings | Ніколи не завантажує повний текст більше ніж однієї одиниці (NFR-16); не пише текст великого документа сам |
   | Виконавець (свіжий контекст на задачу / одиницю) | researcher, writer, analyst — за брифом | Контекстний пакет одиниці (ADR-019 п. 4) | Не виходить за бриф; повертає structured handoff |
   | Рецензент (свіжий контекст на рівень) | critic: одиниця, розділ, інтеграційний | Повний текст свого рівня або підсумки + CLI-результати | Без історії написання; без права схвалення |
3. Аналітик оцінює, що підтримують доступні докази, і межі висновків; остаточну інтерпретацію і рішення про публікацію приймає автор. Approval людини не створює наукової істини, а фіксує рішення. Аналітик викликається за тригерами (нова гіпотеза, метод, метрика, результат, material claim, limitation, зміна висновку).
4. Суперечка analyst ↔ critic: disputed claim + докази обох сторін → додаткова перевірка → ≤2 цикли → рішення автора або `unresolved`.
5. Рецензент не має права схвалення і не змінює raw data.
6. Паралельні виконавці пишуть лише власні одиниці; інтеграцію робить один writer (single writer, ADR-002).
7. Інтеграційний рецензент обов'язковий для дисертації незалежно від результату пілоту C (рішення автора 2026-10-28). Пілот C міряє користь рецензента на рівні одиниці і статті.

## Альтернативи
- **Один агент без окремого рецензента** — відхилено: самоперевірка схильна до підтвердження власного тексту.
- **Шість постійних агентів** — відхилено: вартість і координація без доведеної незалежності.
- **Writer в основному сеансі (rev.1)** — замінено: не масштабується на дисертацію.

## Наслідки
- FR-14 — MUST як можливість; користь окремого рецензента на рівні одиниці / статті міряє пілот C (M5); якщо не виправдовує вартість — спрощуємо цей рівень.
- Handoff між контекстами — короткі structured артефакти і refs, не повні transcripts.
- Механізм запуску паралельних контекстів (subagents у Claude Code, аналог у Codex) перевіряється в Е1 за документацією хоста; ядро CLI від нього не залежить (ASR-03).
