# Research Harness — Implementation Spec v0.2

Date: 2026-10-28. Status: **draft, iteration 1** (files 00–03 and M1 cards). Stage 0, step 4 of `research-harness-spec/stage-0/00-stage0-plan.md`.

This is the instruction set for the implementing agent (Claude Code or Codex). It turns the approved requirements into ordered, verifiable work. It does not re-decide anything approved in stage 0; where it adds a technical choice, the choice is marked **[P]** (proposal, author may change it).

## 1. What you are building

`rh` — a runtime-neutral Python CLI plus thin host adapters (Claude Code first, Codex in M3) that helps one author produce scientific articles and dissertations whose claims, numbers and conclusions are traceable to evidence. Correctness-critical checks live in the CLI, never only in prompts or hooks (ADR-001 rev.2, ASR-03, ASR-04).

The agent conversation is the user interface. The author speaks to the host agent (usually in Ukrainian); the agent calls `rh` and relays results.

## 4. How to work a task card

1. Read the card, the requirements it cites and the files it lists as inputs.
2. Create a branch `m<milestone>/<card-id>-<short-name>`, e.g. `m1/M1-04-state-store`.
3. Implement only what the card asks. Things you notice outside the card go into the PR's "Follow-ups" section.
4. Run the card's **Verify** commands and the standing check `uv run rh-dev check` (defined in M1-01). All must pass.
5. Open a PR using the template in §5.
6. If something in the spec is unclear or contradictory: do the independent technical parts, choose the most conservative reading for the rest, and put a concrete question with options in the PR. Do not stop the whole card for a question that blocks only part of it.

A milestone is finished only when its gate card passes: every test listed for that milestone in `05-eval-base.md` §8 passes (deterministic ones 100%; semantic ones with n and 95% Wilson CI). If a threshold is missed, the author decides (improve / lower threshold with rationale / simplify) and the decision is logged in `harness/evals/results/decisions.md`.

## 5. PR template

The author reads PR descriptions, so write them in his UI language (Ukrainian by default, 02 §1.6); file paths, IDs, commands and requirement IDs stay as they are. Commit subjects are short and in English (machine layer).

```markdown
## Card
M<n>-<NN> <title>

## What changed
<files and behaviour, 3–10 bullets>

## Requirements covered
FR-…, NFR-…, ADR-… ; tests T…

## Verification
<exact commands run and their summarized output; failing tests must be zero>

## Reuse
<adoption records added or "none">

## Deviations from spec
<what differs and why, or "none">

## Questions for the author
<numbered, each with options and your recommendation, or "none">

## Follow-ups
<out-of-scope observations>
```
