# M2 — Vertical slice: literature / conceptual article

Goal (ADR-007 rev.3, `03-requirements-v0.2.md` §7): the research lab (literature access, local library with quote check, synthesis desk, lab journal) and the research cycle; claims, unit briefs with author contribution points, drafting, unit summaries, context packs, draft export to `.docx`. At the end of M2 the harness can take a topic to a draft review article with traceable claims — without the M3 gates, critics hierarchy and verified export.

Requirements: FR-02, 03, 04, 07, 08, 20, 22, 29, 21 (create), 43 (export), 45 (contribution points), 47, 48, 52, 53 (recording), 54 (parts 1–3, 5), 55, 56; NFR-03, 09, 14, 16. FR-24 for every adopted file.

Exit criterion (`05-eval-base.md` §8): **all M1 tests + T01, T02, T03, T06, T07, T11 (draft), T20, T22, T30, T43, T46 (export), T49, T51, T52, T57, T58 (recording), T59, T60 (baseline), T61, T63** — deterministic 100%. Semantic: on F4-W baseline MX, MV, MS with n and 95% Wilson CI; **MF = 0 for critical claims on F4-W**; F4-H first run, report only (run by the author); zero fabricated sources in the draft export.

> **Reminder (must be sent).** The chat that starts M2 — the first one preparing fixtures (M2-14) or the M2 gate (M2-15), whichever comes first — sends the author a **separate message** that he builds the F4-H holdout himself before the M2 gate: picks a sub-topic (not formative assessment, not his first case), 12 sources, writes a test manuscript with seeded defects, annotates the reference, encrypts the archive and creates `holdout.lock.json` (`05-eval-base.md` §2, §4; `08-evals-runbook.md`). ### M2-02 Local library and quote check

**Goal.** Page-accurate local text of every legal full text, a full-text index, and a deterministic check of every quote and excerpt.

**Requirements / tests.** FR-54 part 2, NFR-11; `06-research-agent.md` §3.2; **T59 (library and quote parts)**.

**Depends on.** M2-01.

**Reuse.** None (pypdf / pdfminer.six as dependencies, 01 §3).

**Files.** `research_harness/library/{extract.py, pagemap.py, index.py, quotes.py, normalize.py}`, tests, fixture: F5h (author's real SAGE PDF, private, outside git — test is skipped with a clear message when the file is absent) + a synthetic two-column PDF generated in tests.

**Steps.**
1. Extraction per page into `sources/pagetext/<S>.jsonl` with method and a quality score.
2. Page map: PDF page ↔ printed page from `pages.first` or running headers; `explicit[]` when offsets vary; `unknown` otherwise.
3. SQLite FTS5 index `.rh/library.sqlite` (gitignored, rebuildable by `rh library index`); `rh library search`, `rh library page`.
4. Normalization for quote check (NFC, whitespace, soft hyphens, hyphenation at line ends, quote marks, Ukrainian apostrophe variants ʼ ’ ').
5. `rh quote check`: every excerpt and every quoted span in a unit is searched on the cited page (±1 across a break, recorded); results → findings `quote.not_found_on_page`, `quote.locator_mismatch`, `quote.printed_page_unknown`; low-quality pages → `unverifiable`.
6. Instruction-like text in sources → `source.injection_suspect` finding; the text is stored as data only.

**Verify.**
```
uv run pytest tests/integration/test_library.py -q
```

**DoD.** T59 (library part): text stored per page with both numberings where derivable (F5h: PDF page 1 = printed p. 592); an invented quote and an inexact quote (one word changed) are both findings; a correct quote across a page break passes and is recorded as such. Nothing under `sources/fulltext|pagetext` or `.rh/library.sqlite` is tracked by git.

### M2-03 Search plan, search log and lab journal

**Goal.** No search without a plan; every query, manual export and dead end is recorded.

**Requirements / tests.** FR-03, FR-20, FR-54 part 5, FR-56 (plan); **T59 (≥3 adapters, log), T61 (stop recording)**.

**Depends on.** M2-01.

**Reuse.** OPM #4 literature-engine — procedure text adapted into the researcher skill in M2-13; here only the data side.

**Files.** `research_harness/lab/{plan.py, searchlog.py, screening.py, journal.py}`, schemas `search-plan`, `search-log`, `lab-journal`, CLI handlers, tests.

**Steps.**
1. `rh search plan --file F`: validates resources against the policy, queries per resource, inclusion / exclusion, saturation rule, budget; versioned.
2. `rh search run --adapter A --query Q`: runs through the M2-01 adapter, appends a log line, adds candidates to the registry.
3. `rh search log …`: manual searches and exports (Scopus, WoS, Scholar, НБУВ) with exact query, date, result count, export hash — the agent prepares the query string in the target syntax and gives it to the author (06-research-agent §3.1 "Ручний експорт").
4. `rh screen`: include / exclude with reason.
5. `rh lab journal add`: question, hypothesis, plan change, dead end, deviation, cost, model ID; journal is append-only.
6. Stop recording: `rh search stop --reason saturation|budget|author --uncovered F` writes the stop and the uncovered report.
7. Status shows search coverage per resource (ok / unavailable / not checked).

**Verify.**
```
uv run pytest tests/integration/test_search.py -q
```

**DoD.** T59 (log part): a session across ≥ 3 adapters (mocked) + one manual Scopus export produces a complete log (query, resource, date, status, counts, hash). T61: budget exhausted before saturation → stop recorded with reason and an uncovered report; saturation reached → stop recorded. Search without a plan → exit 3.
